# 05 · 实战踩坑与排障（先读这个再动手）

本文件是一次真实交付（2026-10，示例高校 → 飞书日历 + 多维表格 + Excel）的完整教训。按“最可能让你卡住”的顺序排。

## 1. 取数：不要用 UI 自动化点课表

先后失败的三条路：

1. **操作系统级 UI 自动化**：内置 Computer Use 在 Windows 上无法可靠判定 Edge 当前 URL，直接中止回合。→ 放弃。
2. **浏览器扩展桥接**：扩展与 CLI 版本不一致时报 `Unknown tool: list_browser_tabs`；升级后才可用。
3. **桥接会话管理**：`navigate` 后再 `snapshot` 常报 `session tab was closed — navigate first to recreate`；同一桥接同时连着 Chrome 和 Edge 时会“借用”到错误标签，导致已登录的教务页丢失。

**正确姿势**：让用户在 Edge/Chrome 里保持教务页登录，用桥接 `find_tab(url, active:true)` 固定到该标签，然后在该页上下文 `fetch('/new/desktop/getCalendar', ...)` 一次拿全学期 JSON，立刻落盘。拿不到就让用户把页面切到前台再试，**不要退回逐格点页面**。

## 2. 官方“导出”不是数据源

`printCalendar` 导出的 xls 只有课程简称 + 周次网格，没有起止钟点、没有授课内容、没有教师、没有教室（部分）。用户最初的抱怨就是“缺少时间和课程内容”。

它的唯一用途：**交叉校验**。底部“课表摘要”的 若干行规则展开 = N 条排课，正好等于接口的 N 条；课程若干门也对得上。数量不一致就说明接口少给了，必须停下来查。

## 3. 飞书桌面版 UI 操作靠不住

- 用 Computer Use 操作飞书客户端时被用户按 Esc 中断，且窗口最小化/坐标几何不可用等问题频发。
- 结论：**飞书侧一律走 lark-cli（API）**，不要点客户端。需要用户操作的只有 OAuth 授权页。

## 4. 授权：设备码 10 分钟，别提前点

真实事故链：

1. 生成设备码后，我还在写/调试脚本；
2. 用户过了一段时间才点链接 → 页面 `错误码 20001 请求不合法`；
3. 误判成“链接被截断/打码”，反复生成新链接排错。

**结论**：

- `flow_id`/`device_code` 里出现连续 `O`（如 `...xROOOOOOOOOO2fGR...`）是**飞书真实格式**，不是脱敏；照原样传即可，别“修”。
- 设备码有效期 **600 秒**。**先把所有脚本、payload、QR 生成器准备好，再生成设备码**，让用户立刻扫。
- 拿到 `device_code` 存到文件，授权完成后用 `--device-code` 从文件读，避免手抄出错。
- `auth status --verify` 显示 user `missing`（refresh token 过期）时，CLI 会清空本地身份，必须重走设备码；`--as bot` 顶替不了日历写入。

## 5. 日历写入：三个致命细节

1. **时区**：`start_time.timestamp` 是秒级 Unix，必须显式 `UTC+8` 换算。本机在 America/Chicago 时，用 `datetime.timestamp()` 会整体差 8 小时，且 `+get` 返回的 `datetime` 带 `-05:00` 后缀，容易误判为“写错了”。
2. **不要用 `calendar +create`**：它自动加视频会议和 5 分钟提醒，批量课表全部要清理；用底层 `calendar events create`。
3. **同课多教室**：教务系统里 2026-11-18 示例实验课有 B201/B202 两条平行记录；不合并的话日历里会出现两条重叠同名日程，用户会当 bug。合并后地点写 `B201/B202` 并在描述注明。

## 6. Windows 编码：三个不同层面的坑

| 现象 | 根因 | 处理 |
|---|---|---|
| Python `json.load` 报 `UnicodeDecodeError: 0xff in position 0` | Windows PowerShell 5.1 的 `>` 重定向写的是 **UTF-16LE + BOM** | 用 Python 自己写文件，或读取时判 BOM 走 `utf-16` |
| 控制台输出的中文全是 `璇剧▼` 之类 | 控制台代码页/编码不是 UTF-8 | 结果写 UTF-8 文件再用文件读取查看，别信控制台回显 |
| 脚本打印的中文在日志里乱码 | 同上 | 日志统一 UTF-8；Python 加 `flush=True` 保证顺序 |

## 7. 数据口径：三个“看起来像 bug 但其实是源数据”的地方

1. **部分记录无教学场地**：慕课、部分实验课在教务系统里 `jxcdmc` 就是空。表格渲染「未提供」，CSV/多维表格留空，**不要编教室**。
2. **若干处时间重叠**：可能是上课撞考试（示例课程D vs 示例课程C 考试）、不同课程重叠、同一课程多教室。全部写进「数据提示」并在最终回复里点名。
3. **部分记录内容时段与排课不一致**：示例实验课B 排课到 18:00，授课内容写 10:20–15:40。保留排课值 + 原文，加标注。

另有两个**数量口径**，别自己算错：

- 记录数与「课程×时段」数会因“同课同时段两间教室”的平行记录而不等：合并前是记录数，合并后是「课程×时段」数。
- CSV 物理行数可能大于记录数，因为授课内容里有引号内换行；判定完整性要按 CSV 解析后的记录数，不是行数。

## 8. 验收必须独立

- 生成脚本自带的 check 只能证明“按我的假设写对了”。
- 本次做法：另写 readback/verify 脚本逐字段比对，再让一个**独立 agent** 只读审计三件套 + 官方 xls，输出 PASS/FAIL 清单（A–G 全 PASS，24k+ 项检查）。发现的问题都是 P2（CSV 无 BOM、空值渲染三套约定等）。
- 交付前最后一步：确认文件哈希在审计前后未变，避免“审计完又被脚本覆盖”。

## 9. 长任务稳定性

- 一次交付可能跨多轮、中途被打断（本次原会话撞到模型额度上限）。**每个阶段都落盘**：`raw.json`、`normalized.json`、`base_records.json`、`push_log.json`、`readback.ndjson`，任何一步都能续跑。
- 幂等键/源记录 ID 是续跑的保险：重跑不会重复、能对比差异。
- 写入前先 `--limit 1` 单测一条，`+get` 核实后再全量。

## 10. 隐私边界

课表 = 个人日程 + 常去地点，属敏感个人信息：

- 只写用户自己的飞书空间（主日历 / 自己创建的 Base）；
- 不把课表内容发到群聊、不外发；
- 日志里不要塞无关个人信息；
- 删除类操作（清历史课程、删 Base）必须先给条数、要用户明确同意。
